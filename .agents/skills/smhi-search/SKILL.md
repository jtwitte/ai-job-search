# SMHI Search Skill

Search SMHI's own job listing page - **deliberately the Swedish-language version**
(`smhi.se/jobba-pa-smhi/lediga-tjanster`), which carries more open postings than any English
equivalent (per Jan-Torben's explicit instruction when this skill was set up). No
authentication, no API key, and **zero runtime dependencies** - it runs with just `bun`.

> Single-company skill, generated by `/add-portal` (2026-08-11). SMHI is already a declared
> Target Sector (government agencies) in CLAUDE.md. Per repo policy this lives in the fork
> rather than being merged upstream.

## When to use this skill

- List or search SMHI's currently open roles
- Get the full description of a specific SMHI job listing

## Commands

### Search job listings

```bash
bun run .agents/skills/smhi-search/cli/src/cli.ts search [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — keyword filter over title + summary (client-side; the listing page has no search API). Omit to list everything currently open.
- `--page <n>` — page number (1-indexed).
- `--limit <n>` / `-n <n>` — results per page / cap. Default 20.
- `--format json|table|plain` — default `json`.

All open roles come back in a single page fetch — SMHI's listing has no pagination of its
own, confirmed live (8 items, all in the initial HTML).

### Fetch full job detail

```bash
bun run .agents/skills/smhi-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the numeric ReachMee job ID from `search` results (e.g. `834`). A bare id re-fetches
the current listing to resolve a live application URL (see `url-reference.md` for why — the
ReachMee link carries a per-tenant token this CLI deliberately doesn't hardcode). A full URL
(as returned by `search`) works directly. Returns the full description.

## Usage examples

```bash
# Everything currently open at SMHI
bun run .agents/skills/smhi-search/cli/src/cli.ts search --format table

# GIS-specific roles (matches Jan-Torben's GIS upskilling direction)
bun run .agents/skills/smhi-search/cli/src/cli.ts search -q "GIS" --format table

# Full details for a specific job
bun run .agents/skills/smhi-search/cli/src/cli.ts detail 834 --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Data is from SMHI's own Sitevision-rendered listing page (search) and its ReachMee ATS job pages (detail) — no credentials required.
- **The `date` field's exact meaning is inferred, not confirmed** — the listing card's `<time>` value is most likely the application deadline ("sista ansökningsdag"), not a posting date, based on its `23:59:00` time-of-day and the observed date spread. Treat it as "apply by," not "posted on." No `--jobage` flag is offered because of this uncertainty — filtering "posted within N days" on what's probably a deadline field would be misleading.
- `--query`/`-q` is a client-side filter, not a server parameter — the listing page has no search API. Fine for SMHI's small open-role count; this isn't built for scale.
- See `url-reference.md` for the full endpoint reference and the reasoning behind not hardcoding ReachMee's validator token.
