# Reach Subsea Search Skill

Search Reach Subsea's own careers page (`reachsubsea.no/careers/`), which server-renders its
open positions directly into HTML - no authentication, no API key, and **zero runtime
dependencies** - it runs with just `bun`.

> Single-company skill, generated by `/add-portal` (2026-08-11). Reach Subsea is already a
> declared Target Sector (industry) in CLAUDE.md. Per repo policy this lives in the fork
> rather than being merged upstream.

## When to use this skill

- List or search Reach Subsea's currently open roles
- Get the full description of a specific Reach Subsea job listing

## Commands

### Search job listings

```bash
bun run .agents/skills/reachsubsea-search/cli/src/cli.ts search [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — keyword filter over title + workplace (client-side; the listing page has no search API). Omit to list everything currently open.
- `--page <n>` — page number (1-indexed).
- `--limit <n>` / `-n <n>` — results per page / cap. Default 20.
- `--format json|table|plain` — default `json`.

All open roles come back in a single page fetch — no pagination observed on Reach Subsea's
own listing page.

### Fetch full job detail

```bash
bun run .agents/skills/reachsubsea-search/cli/src/cli.ts detail <projectId|url> [--format json|plain]
```

`projectId` is the numeric id from `search` results (e.g. `66974`). A bare id re-fetches the
current listing to resolve the full application URL (HR-Manager, Reach Subsea's ATS vendor,
requires `DepartmentId`/`MediaId` alongside the id, which aren't derivable from it alone —
see `url-reference.md`). A full URL (as returned by `search`) works directly. Returns the
full description.

## Usage examples

```bash
# Everything currently open at Reach Subsea
bun run .agents/skills/reachsubsea-search/cli/src/cli.ts search --format table

# Location-specific
bun run .agents/skills/reachsubsea-search/cli/src/cli.ts search -q "Haugesund" --format table

# Full details for a specific job
bun run .agents/skills/reachsubsea-search/cli/src/cli.ts detail 66974 --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Data is from Reach Subsea's own careers page (search) and their Talentech/HR-Manager ATS ad pages (detail) — no credentials required.
- **Only one role was open at the time this skill was verified** (Senior Project Manager, Haugesund) — the multi-item parsing logic is confirmed against that one real posting plus a same-shape synthetic second card in the test suite, not two real postings side by side. Re-verify if results ever look wrong with 2+ open roles.
- `--query`/`-q` is a client-side filter, not a server parameter — the listing page has no search API. Fine for Reach Subsea's small open-role count; this isn't built for scale.
- See `url-reference.md` for the full endpoint reference, including why `candidate.hr-manager.net`'s robots.txt is followed carefully (blanket disallow with a narrow, explicit `Allow` carve-out for exactly the ad-page path this CLI uses).
